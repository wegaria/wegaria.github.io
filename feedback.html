Feedback widget

feedback embeds the widget of a separate feedback service on every page: a "Feedback" button with which visitors can leave comments, mark an element of the page and attach a screenshot. Wegaria only embeds the widget; the feedback service itself is a separate product and is not part of Wegaria.

feedback:
  key: pk_abc123           # public key of the project in the feedback service
  path: /_feedback         # optional, default /_feedback; one path segment
  identify: true           # send name, e-mail and id of the signed-in person (optional, default false)
Field Default Meaning
key required The project's public key (pk_ followed by letters and digits).
path /_feedback One path segment under which the reverse proxy serves the widget on Wegaria's own origin. It must not collide with a built-in page (/assets, /admin, /auth, /api, /status, /service, /news, /search, /my, /forms, /healthz, /favorites).
identify false Send the signed-in user's id, name and e-mail with their feedback.

How it works

  • Wegaria inserts only a script tag: /_feedback/widget.js (the path can be changed with path). It does not serve the widget itself and does not forward anything.
  • A reverse proxy, for example Traefik, sends the path on Wegaria's origin to the feedback service. Because of this, the Content-Security-Policy stays unchanged (script-src 'self', connect-src 'self') and CORS is not involved.
  • Forward only /_feedback/v1 and /_feedback/widget.js, nothing more. Otherwise the administration and API of the feedback service would be reachable under Wegaria's address. A ready-made Traefik rule is in Deployment; the documentation of the feedback service describes serving it under the path of your own application.
  • Without a proxy rule the path answers 404. The widget then simply does not appear and the site works as normal.
  • identify sends the data as a claimed identity; the feedback service marks it as "stated", not verified. It appears only in the HTML of the signed-in person themselves.
  • In the feedback service, enter the public URL of Wegaria under its allowed origins.

Trying it with the demo

FEEDBACK_KEY=pk_... npm run demo adds the block to the demo configuration. Start Traefik locally with demo/traefik.yml (the command is written in that file) and open http://localhost:3200. The file demo/wegaria.generated.yaml is a generated artefact and is not committed.
