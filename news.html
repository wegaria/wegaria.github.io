News

news shows entries from RSS or Atom feeds: a box in the side column of the start page (the newest limit, default 5) and the page /news (up to pageLimit, default 50), reachable in the menu as "News".

news:
  limit: 5          # entries in the side column of the start page (1 to 50)
  pageLimit: 50     # entries on /news (1 to 200)
  feeds:
    - { name: Intranet, url: https://intranet.example.com/feed.xml, cacheSeconds: 600 }
    - { name: Personnel, url: https://hr.example.com/feed.xml, auth: { bearer: "${file:/run/secrets/hr_feed}" }, access: { groups: [staff] } }
Feed field Default Meaning
name required Shown as the source of each entry. Must be unique.
url required http(s) URL of the feed.
auth none { bearer }, { basic: { user, password } } or { headers }; sent only from the server.
access none Who may see the entries of this feed.
timeoutMs 5000 Request timeout (max. 30000).
cacheSeconds 600 Cache lifetime; refreshed in the background.

To show the news box in the side column, keep news in home.side (it is part of the default). See Appearance.

Behaviour

  • Wegaria only reads the feed URL. How the feed is produced (for example from SharePoint) is not its concern. Supported: RSS 2.0, RSS 1.0, Atom.
  • access applies per feed as with tiles. Feeds the user may not see are not fetched for that user. If the user sees no feed, /news and the menu entry do not exist for them.
  • Several feeds are merged by date. If more than one feed is visible, name is shown as the source on each entry.
  • On /news, a search field replaces the navigation row and filters the news: immediately while typing (script), and without JavaScript or for links through /news?q=.... The same rule as in the global search applies: every word must be the start of a word in the title, source or excerpt, ignoring case and umlauts. What is filtered is what the feed delivers (at most pageLimit entries).
  • Title, date, link and an excerpt shortened to plain text are shown. HTML from the feed is never output; links only with http(s).
  • Like providers, responses come from a cache and are renewed in the background. A dead feed shows the last entries, or "Nicht verfügbar" (not available), and slows nothing down.
  • Redirects are not followed (credentials stay with the server), so enter the final URL.
  • The size of a feed is limited to 1 MB.
