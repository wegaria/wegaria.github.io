Getting started

Wegaria is a single Node.js process with an SQLite database. It is configured with one YAML file (wegaria.yaml) plus optional Markdown and YAML content files.

Try the demo

npm install
npm run demo         # http://localhost:3100

The demo contains example content and mock backends (status, Docker labels, news feed, webhook). It restarts when the code changes (tsx watch).

  • The demo starts Wegaria in dev authentication mode with a fixed user (groups it and staff; see demo/wegaria.yaml).
  • Example submissions are stored in demo/.state/. Delete that directory to reset the demo. The git archive and the database used by the demo also live there.
  • http://127.0.0.1:3101/toggle-gitlab switches the status of the "Gitlab" application in the mock backends.
  • Webhooks that are delivered appear in the console.
  • To use your own demo environment (your own wegaria.yaml, content/ and assets/), keep it in any other directory, for example in a private repository that contains this project as a submodule, and run DEMO_DIR=/path/to/demo npm run demo. State is then stored in <DEMO_DIR>/.state/.
  • To try the feedback widget with the demo, see Feedback.

Development

npm install
npm run dev          # http://localhost:3000, uses config/wegaria.yaml
npm test
npm run gen:schema   # writes config/wegaria.schema.json for IDE completion
npm run build && npm start

npm run gen:schema generates the JSON schema from the configuration schema in src/config/schema.ts. Point your editor's YAML support at config/wegaria.schema.json to get completion and validation while editing wegaria.yaml.

Environment variables

Variable Default Meaning
WEGARIA_CONFIG config/wegaria.yaml (in the container: /config/wegaria.yaml) Path to the YAML configuration file. Content, assets and status directories are resolved relative to it.
WEGARIA_DATA ./data (in the container: /data) Directory for the SQLite database wegaria.sqlite3 (submissions, action queue, audit log, sessions, favourites) and, with native OIDC, session.key.
PORT 3000 TCP port the server listens on.
NODE_EXTRA_CA_CERTS – Path to an extra CA certificate (PEM) for internal backends and SMTP servers that use a private CA.

Secrets inside wegaria.yaml are never written in plain text. Use ${env:NAME} or ${file:/run/secrets/name}; see Authentication.

A first configuration

title: Intranet
auth:
  mode: dev                 # fixed user from this file, for development only
  groups: [staff]
sections:
  - title: Daily work
    items:
      - { title: Mail, url: https://mail.example.com, icon: "lucide:mail" }
      - { title: Wiki, url: https://wiki.example.com, icon: "lucide:book-open" }
  - title: Administration
    access: { groups: [it] }   # only members of the group "it" see this section
    items:
      - { title: Monitoring, url: https://monitoring.example.com }

Everything else (status, news, service area, footer, ...) is optional and switched on by adding the corresponding block. The pages of this guide describe each block.

Tile ids are used to refer to a tile from other places (favourite defaults, affects in incidents, apps in service pages). A tile gets the id given in id: or otherwise a slug of its title ("Mail" becomes mail). Ids must be unique.

Reloading the configuration

Changes below the config directory (the YAML file, content/, assets/, status/) are picked up automatically, without a restart.

  • If the new file is invalid, the previous version stays active. The error is written to the log and shown at the top of the page to members of adminGroups.
  • auth and baseUrl are read only at start-up. Changes to them are rejected until Wegaria is restarted.
  • Changes to docker: need a restart.
  • Secrets from ${file:...} and ${env:...} are re-read only when the YAML file changes.

Other top-level settings

Setting Default Meaning
title Wegaria Page title.
subtitle none Line under the greeting on the start page; leave it out for no line.
lang de Language code. The setting exists, but the interface is currently German only and not translated yet. It currently also selects the CSV delimiter (see Service area).
baseUrl none Public URL of Wegaria. Required for oidc and used for CSRF (Origin) checks behind a proxy.
timezone server zone IANA zone name such as Europe/Berlin for displayed times, greetings and dates typed in the admin forms. In containers the server zone is usually UTC.
adminGroups [] Groups that see operational notices (configuration reload errors, hints about unknown ids) and can use /admin.
refreshSeconds 0 Reload the page periodically (0 = off).
auditRetentionDays 365 Submission records and audit entries older than this are deleted.

The remaining blocks are described on their own pages: branding, home and footer in Appearance; sections, docker and icons in Applications; providers, widgets and incidents in Status; news in News; service, smtp and targets in Service area; auth in Authentication; feedback in Feedback.
