Authentication and access

Modes

Mode Purpose
dev A fixed user from the configuration; for development only.
headers Forward auth (Traefik with Authelia or oauth2-proxy). Identity headers are accepted only from trustedProxies.
oidc Native sign-in (authorization code with PKCE), server-side sessions, groups from the ID token or userinfo.

Wegaria builds a principal (id, name, e-mail, groups) from one of these. Access decisions are always made on the server.

dev

auth:
  mode: dev
  user: dev                    # default "dev"
  name: Dev User               # default "Dev User"
  email: dev@example.com       # default "dev@example.invalid"
  groups: [it, staff]
  logoutUrl: https://example.com/logout   # optional

Never use dev in production: everyone is signed in as that user.

headers (forward auth)

auth:
  mode: headers
  trustedProxies: [10.250.0.0/24]   # IPs/CIDRs of the reverse proxy; required
  headers:                          # defaults shown
    user: Remote-User
    name: Remote-Name
    email: Remote-Email
    groups: Remote-Groups
  groupsSeparator: ","              # default ","
  groupNormalize: none              # none | strip-leading-slash | last-segment
  logoutUrl: https://auth.example.com/logout   # optional

Security warning. Headers are trusted only when the request comes from an address in trustedProxies. That check knows only the source address.

  • Wegaria must not be reachable directly: anybody who can reach it could set the headers themselves. The Compose example publishes no ports.
  • Only the reverse proxy (and Wegaria) belong in the network listed in trustedProxies, ideally a dedicated network per application. Another container in the same network could forge the headers.
  • The proxy must overwrite or remove client-supplied identity headers. With Traefik, authResponseHeaders must list all four headers Wegaria reads. See Deployment.

groupNormalize fixes group paths such as /it/admins that Keycloak delivers: strip-leading-slash gives it/admins, last-segment gives admins.

oidc

See OIDC details below.

Access rules

Visibility is controlled with access: { groups, deny, public } on sections, tiles, widgets, news feeds, notices, the footer, and (inherited from categories) FAQ pages and forms.

access:
  groups: [staff, it]    # any of these groups; empty or absent = any signed-in user
  deny: [contractors]    # wins over everything
  public: true           # additionally lets anonymous visitors in
  • All rules along the path must allow; deny wins. Filtering is done on the server.
  • Without a rule, all signed-in users see the entry; anonymous visitors only with public: true.
  • Content that may not be seen answers with 404 and does not appear in lists or the search.
  • With oidc, anonymous visitors see nothing at all unless auth.public: true is set (otherwise they are redirected to the login). To release only the state of one service, use status.public (see Status).
  • Groups that may use the administration are listed in the top-level adminGroups.

Secrets

Never write secrets into the YAML. ${env:NAME} and ${file:/run/secrets/name} are replaced when the configuration is loaded. They are re-read only when the YAML file changes (see Getting started). Secrets never belong in content files; webhook secrets and SMTP passwords live in wegaria.yaml.

OIDC details

baseUrl: https://wegaria.example.com     # public URL; the redirect URI is <baseUrl>/auth/callback
auth:
  mode: oidc
  issuer: https://auth.example.com/realms/main
  clientId: wegaria
  clientSecret: ${file:/run/secrets/wegaria_oidc}
  groupsClaim: groups
  groupNormalize: strip-leading-slash   # Keycloak delivers paths such as /it/admins
  public: false                         # true: Wegaria is also reachable without signing in (anonymous visitors see only what is `public`);
                                        # false: redirect to the login
                                        # (`autoLogin: false` is the old name for `public: true`)
Field Default Meaning
issuer required Issuer URL; discovery runs against /.well-known/openid-configuration.
clientId required Client id.
clientSecret none Omit for public clients (PKCE is always used).
scopes [openid, profile, email, groups] Requested scopes.
groupsClaim groups Claim that carries the groups.
groupNormalize none none, strip-leading-slash or last-segment.
sessionHours 8 Session lifetime.
recheckMinutes 15 How often group membership is re-read from the IdP with the refresh token (0 = only at login).
public false See above.
autoLogin true Deprecated; use public (autoLogin: false equals public: true).
allowInsecureHttp false Allow an http:// issuer (local development only).

baseUrl is required with oidc. The redirect URI to register at the IdP is <baseUrl>/auth/callback. auth and baseUrl are read only at start-up.

  • Keycloak: create a "Group Membership" mapper on the client (claim groups). Authelia: groups come through userinfo, which is fetched automatically.
  • Sessions are stored in SQLite ($WEGARIA_DATA/wegaria.sqlite3) and survive restarts and updates. Only a hash of the session id is stored; the ID token (used at sign-out) and the refresh token are stored encrypted (see below). The cookie is HttpOnly, SameSite=Lax, and Secure with an https baseUrl.
  • Group changes apply without a new sign-in: every recheckMinutes (default 15; 0 = only at login) Wegaria asks the IdP again with the refresh token. Groups are updated (audit: auth.groups_changed with added/removed groups). If the IdP rejects the token (user blocked or deleted, session ended there), the user is signed out (auth.revoked). If the IdP is briefly unreachable, the last known groups apply and Wegaria retries after a minute.
    • Keycloak issues refresh tokens by default. Authelia only with the scope offline_access: allow it on the client (scopes, grant_types: [authorization_code, refresh_token]) and add it to auth.scopes. Without a refresh token, Wegaria records a warning at the first login and checks groups only at login.
    • The refresh token and ID token are stored encrypted (AES-256-GCM) in the sessions table. Back up the database accordingly. The key is in $WEGARIA_DATA/session.key (created at first start, mode 0600). Keep that file separately from the database; without it, stored sessions are unusable (users sign in again).
  • Back-channel logout: the IdP can end sessions immediately by calling https://<baseUrl>/auth/backchannel-logout (OIDC Back-Channel Logout 1.0). The signed token is verified: signature, issuer, audience, age of at most 5 minutes, replay protection. Keycloak: set Backchannel logout URL on the client and enable Backchannel logout session required. The endpoint must be reachable directly for the IdP (not behind forward auth). Audit event: auth.backchannel_logout.
  • Logout is a POST (CSRF-protected through an Origin check against baseUrl) and, where supported, also ends the IdP session.
