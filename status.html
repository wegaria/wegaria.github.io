Status and notices

Wegaria has no checker of its own. It reads existing systems through providers, shows their state as a dot on tiles, and adds incident and maintenance notices.

Providers

providers:
  kuma:
    type: uptime-kuma
    baseUrl: https://status.example.com
    statusPage: main
    auth: { bearer: "${file:/run/secrets/kuma}" }
    cacheSeconds: 30
    timeoutMs: 5000
Type Tile reference Source
uptime-kuma monitor: name or id Public status page API (/api/status-page/<slug>); the monitor must be on that page. The slug is set with statusPage.
prometheus query: PromQL /api/v1/query. Result greater than 0 = healthy, mixed = degraded.
gatus endpoint: key, group/name or name /api/v1/endpoints/statuses (the first 100 endpoints).
http none Source for widgets: JSON from baseUrl + path, fields through a JSONPath subset ($.a.b[0]['c']).

Common provider fields:

Field Default Meaning
baseUrl required Base URL of the backend.
auth none One of { bearer: ... }, { basic: { user, password } }, { headers: { Name: value } }. Use ${env:X} or ${file:...}.
timeoutMs 5000 Request timeout (max. 30000).
cacheSeconds 30 Cache lifetime; data is refreshed in the background.

A tile refers to a provider with a status block:

- title: Mail
  url: https://mail.example.com
  status: { provider: kuma, monitor: Mail }       # uptime-kuma
# status: { provider: prom, query: 'up{job="mail"}' }   # prometheus: PromQL that yields > 0 when healthy
# status: { provider: gatus, endpoint: core_mail }       # gatus

Each provider type needs its own reference field (monitor, query or endpoint), and fields of other types are rejected. Providers of type http are for widgets only, not for status.

Behaviour and safety:

  • All queries run in the backend. Credentials (auth.bearer, basic, headers) are never delivered to the browser.
  • Data comes from a cache (cacheSeconds, default 30 s) and is refreshed in the background; only the first request waits for the backend. If a backend fails, the last value is marked "stale" ("veraltet"), otherwise "unknown" ("unbekannt"). Timeout 5 s, responses at most 1 MB, no redirects.
  • Only what the user may see is queried (access also applies to widgets).
  • Values from backends are rendered as text, never as HTML.
  • For internal backends with a private CA, set NODE_EXTRA_CA_CERTS=/path/ca.pem.

Widgets

Widgets show key figures from an http provider. They appear in the side column of the start page when widgets is listed in home.side (see Appearance).

providers:
  api:
    type: http
    baseUrl: https://metrics.example.com
widgets:
  - title: Tickets
    provider: api
    path: /summary
    link: https://helpdesk.example.com
    access: { groups: [it] }
    fields:
      - { label: Open, path: "$.tickets.open", format: number }
      - { label: SLA, path: "$.sla.rate", format: percent }
      - { label: State, path: "$.state", format: text }

path must start with a single /. format is text (default), number or percent; suffix is optional text after the value. The JSONPath subset supports $.a.b[0]['c']; other expressions are rejected by the configuration check.

Incidents and maintenance

incidents: { dir: status, from: [kuma] } switches notices on.

incidents:
  dir: status            # folder with *.incident.md and *.maintenance.md, relative to the config file
  from: [kuma]           # uptime-kuma providers whose status-page incident and maintenance are shown too
  showResolvedDays: 7    # how long resolved incidents stay listed
  announceDays: 14       # how far ahead planned maintenance is announced
  editable: false        # let adminGroups edit notices in /admin/notices

Sources:

  • Files status/<name>.incident.md and <name>.maintenance.md (front matter plus Markdown; templates: config/status/*.example). Incidents have severity (info|minor|major|critical), status (investigating|identified|monitoring|resolved) and an update timeline. Maintenance has start and end. Tiles are linked through affects: [tile-id] (the id: of the tile, otherwise the slug of its title, for example "Mail" becomes mail).
  • Uptime Kuma (from:): the incident (pin) and running maintenance of the status page also appear. Kuma does not name the affected monitors, so they apply generally (not per tile). Only providers of type uptime-kuma may be listed in from.

Date and time inputs are interpreted in the zone timezone (IANA name, for example Europe/Berlin); without it Wegaria uses the server's zone, which in a container is usually UTC. The same zone applies to all displayed times.

Effects:

  • A banner on the start page (active incidents, running maintenance and maintenance planned within announceDays); see Appearance.
  • The /status page with a timeline and "Kürzlich behoben" (recently resolved; showResolvedDays).
  • The status of affected tiles: running maintenance is blue, minor is yellow, major and critical are red.

A notice can only worsen or explain a measured status, never make it look better. If the measured status is worse, it stays, with the notice as the explanation.

access per notice works as everywhere (default: signed-in users; public: true also for anonymous visitors). Typos in affects are reported to adminGroups as hints.

Notice editor

With incidents: { editable: true }, an editor for incidents and maintenance appears at /admin/notices: create, edit, add to the timeline, set to resolved ("Behoben"), delete. It writes the same Markdown files into incidents.dir, so they can still be maintained by hand or through git.

  • The directory must be writable. In a container, mount it separately (for example ./status:/config/status), see Deployment.
  • When saving, the file is rewritten; hand-written comments in it are lost.
  • All changes are in the audit log (notice.created|updated|deleted).

Public status page

/status is also reachable for visitors who are not signed in (with native OIDC without a redirect to the login). Only what is released with access: { public: true } is visible. If nothing is public, the page says so instead of claiming that everything is fine.

Only the state of an internal service public: status: { provider: ..., public: true } on a tile shows name and state on /status (and in the overall state of the quick menu) even to visitors who may not see the tile. The tile itself stays invisible (start page, search, application page). Provider detail texts (error messages, host names) are given only to authorised users. In Docker labels this is wegaria.status.public.

Whole pages without login: auth.public: true (oidc only; with headers, the proxy decides whether anonymous requests get through).

Behind Traefik forward auth, /status must be routed past the Authelia middleware for this; see Deployment.
