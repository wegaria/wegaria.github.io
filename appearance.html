Appearance

The whole look is driven by CSS variables (colours, spacing, radius, font; see :root in src/views/styles.ts). Colour means state (green, yellow, red, purple); the brand gets a single, calm accent.

The interface is currently German only. Labels in this guide are given as they appear in the UI, with an English gloss on first use.

Branding

title: Intranet                # page title
subtitle: Internal services    # optional: line under the greeting on the start page; omit for no line
branding:
  logo: logo.svg          # file in config/assets/ or a URL
  accent: "#2457c5"       # links, current page, primary buttons
  accentDark: "#7f9fe6"   # optional; otherwise accent is lightened in dark mode only as far as readability (AA) needs
  radius: default         # sharp | default | round
  font: "Inter, system-ui, sans-serif"
  customCss: true         # loads config/assets/custom.css last; it may override any variable
  surveyTheme: mytheme.json   # optional SurveyJS theme, see "Appearance of forms" in the service area page
Field Default Meaning
logo none URL, or a file name inside config/assets/.
accent #2457c5 Brand colour as hex (#rgb or #rrggbb).
accentDark derived Brand colour for dark mode.
radius default Corner rounding: sharp, default, round.
font none A CSS font-family list (letters, digits, spaces, commas, quotes, dots, dashes only; max. 200 characters).
surveyTheme none File name of a .json theme inside config/assets/. See Service area.
customCss false Load assets/custom.css (next to wegaria.yaml) after the built-in styles.

custom.css can, for example, set :root{ --bg:#fff; --container:1280px }, or change the greys in dark mode with @media (prefers-color-scheme:dark).

The dark mode is a soft, neutral anthracite (--bg:#2d2f33). Alternatives are shown in docs/ui/dark-palettes.html in the repository.

Start page

The start page puts work first. At the top is the greeting ("Guten Morgen" until 10:59, "Guten Tag" until 17:59, "Guten Abend" until 21:59, then "Gute Nacht", in the zone timezone, kept current by the clock), date and clock. Below it is "Meine Anwendungen" (my applications: personal favourites, marked with a star on each tile; every application appears only once, the rest is listed under "Weitere Anwendungen", more applications) and a side column that you compose yourself (side: the areas with the overall status in words, news, key figures).

The built-in greetings are German. To change the language of the greeting for a time window, use greetings (below).

home:
  clock: true                 # date and clock (the clock keeps running via a small script)
  greetings:                  # special greeting for a time window; replaces the standard greeting (the first match wins)
    - { from: "12:30", to: "13:00", text: Guten Hunger }                       # "Enjoy your meal" at lunch time
    - { from: "15:00", to: "18:00", days: [fri], text: Schönes Wochenende }    # days is optional; a window may run over midnight
  noticeBanner: major         # from this severity on, an incident interrupts the start page - but only if it affects MY applications
  defaults:                   # suggestions until someone sets their own favourites (tile ids); the first star takes them over
    - { groups: [staff], tiles: [wiki, mail] }
  side: [search, notices, news]   # blocks of the right column, top to bottom (default); more: widgets (key figures)
  navigation: quick               # quick: "Schnellauswahl" (quick menu) above the side column | menu: in the menu behind the user circle
  header: hero                # hero (default) | bar - see below
  background: { image: hero.jpg, imageDark: hero-dark.jpg, dim: 0.5, position: center }   # optional, images in config/assets/
  userLinks: true             # let signed-in users add their own links (default true)
Field Default Meaning
clock true Show date and a live clock at the top.
header hero hero: no solid top bar on the start page, navigation and user sit over the greeting. bar: the same bar as on every other page.
background.image none Image file in config/assets/ (landscape, at least 1600 px wide). Allowed: jpg, jpeg, png, webp, avif, as plain file names.
background.imageDark none Optional darker variant for dark mode.
background.dim 0.55 How much the image is darkened (0 to 0.9).
background.position center A CSS background-position such as center, top or 50% 30%.
side [search, notices, news] Blocks of the side column: search, notices, news, widgets.
greetings [] Special greetings. from and to are 24-hour times (HH:MM, to exclusive, must differ); text is up to 40 characters; days is an optional list of mon to sun (evaluated in timezone).
userLinks true Let signed-in users add their own links.
navigation quick Where Status, Service and News are linked on the start page: quick or menu.
noticeBanner major One of info, minor, major, critical.
defaults [] Favourites by group (groups empty = everyone; tiles = tile ids). Unknown tile ids are rejected by the configuration check.

Header of the inner pages

With header: hero, all pages except the administration share the header of the start page:

  • the image of home.background (darkened), or the brand colour if there is no image;
  • on the left the breadcrumb and the title of the page (description, tags, search);
  • in the middle the optional branding.logo (in the same place on every page);
  • on the right the "Schnellauswahl" (quick menu: Start, Status, Service, News) and the user circle.

Breadcrumbs lead back ("Start / Service / ..."). The search sits with the content: on the service start page and the search page above the results, and on the news page as a filter above the entries.

The status page stands on its own: it has the full look of the start page (image behind everything, frosted glass) and also works without signing in. Signed-in users always see the quick menu at the top; visitors who are not signed in find the login in the user menu. When the status page is opened on its own, nothing of Wegaria surrounds it; when the visitor comes from a page of Wegaria (referrer), "← Zurück" (back) and the quick menu appear.

The administration also has this header (breadcrumb "Start / Administration", title, logo, quick menu, user). Below it stays the strip "Administration · nur für Administratoren sichtbar" (visible to administrators only), and the title is repeated in the content area.

With header: bar, the classic white bar stays on all pages and the start page looks like the others.

Hero instead of a top bar (header: hero)

On the start page there is no fixed bar. At the top are the greeting, the clock and the user circle. The menu behind the circle contains only personal items ("Meine Anfragen", my requests; "Administration"; "Abmelden", sign out) and the search. On all other pages the bar stays; on phones it is the menu.

Background image

The image sits behind the hero (not behind the whole content, so text always sits on a solid surface). A gradient darkens the image by dim so the white text stays readable (recommended 0.45 to 0.6; bright images rather higher). Without an image there is a subtle gradient in the accent colour.

Notices in levels

Only an incident of severity noticeBanner or higher that affects an application visible to the user (or a critical one without an assignment) appears as a narrow strip. Everything else (hints, impairments, maintenance) sits quietly in the side column; maintenance never interrupts. The overall situation is shown in words under "Status" in the quick menu (there is no coloured dot in the navigation).

Side column (home.side)

  • search: the search with live hits (see Applications). It takes over the search from the user menu.
  • notices: hints and maintenance.
  • news: the newest entries; see News.
  • widgets: the key figures from widgets:; see Status.

What is not in the list does not appear and is not queried. Key figures must therefore be listed deliberately.

Status, Service and News are reached from the start page through the "Schnellauswahl" (quick menu). Its heading "Schnellauswahl ▾" sits level with "Meine Anwendungen", and the search field below it lines up with the first row of tiles. Under "Status" the overall situation is given in words. With navigation: menu these entries are in the menu behind the user circle instead. On all other pages the navigation reads Start, Status, Service, News.

Customise mode ("Anpassen")

The link "Anpassen" (customise) next to the first heading (/?anpassen=1; "Fertig", done, leads back) shows an eye next to the star on every tile. Hide removes the application from the user's own start page (also from the favourites). It can still be found through the search, and in customise mode it is listed under "Ausgeblendet" (hidden) so it can be brought back. This is stored per user in the database (only tile ids, at most 200) and works without JavaScript.

searchOnly: true on a tile (Docker label: wegaria.searchOnly) is the variant for administrators: never on the start page, not even hideable, but found by the search. Use it for rarely needed applications.

Favourites

Favourites are stored per user in the database (only the tile id, at most 24) and work without JavaScript. Wegaria deliberately does not record what anyone opens.

Until a user sets favourites, home.defaults applies by group. The first star the user sets takes over the defaults as the user's own favourites.

Own applications ("Eigene Anwendungen")

Signed-in users can add their own links in customise mode (title, address and, if icons.dir is configured, optionally an icon name such as grafana). They appear in a narrow area "Eigene Anwendungen" (own applications) below "Meine Anwendungen" (icon and title only, no status). They are private: only the owner sees and finds them. At most 50 per user.

Only http(s) addresses without credentials are allowed. Foreign image URLs as icons are deliberately not supported. Switch the feature off with home.userLinks: false. There is no editing: remove the link and create it again.

Footer

An optional footer under every page, for example for contact persons, availability or imprint and privacy notice:

footer:
  text: |
    Questions about Wegaria: **Anna Example**, phone 1234, [anna@example.com](mailto:anna@example.com)
    · [Imprint](https://example.com/imprint)
  access: { groups: [staff] }   # optional; without it everyone sees the footer, including anonymous visitors

text is Markdown (1 to 2000 characters; raw HTML is escaped and javascript: links are not possible). With access the footer can be limited to groups (for example internal phone numbers); public: true additionally shows it to anonymous visitors. Changes are reloaded with the configuration. The footer sits inside the hero wrapper and is pinned to the bottom on short pages.

Icons

Tiles (and categories in the service area) get an icon with icon::

- { title: Mail,    url: ..., icon: "lucide:mail" }          # built-in line icon, follows the design colours
- { title: Wiki,    url: ..., icon: "wiki.svg" }              # file from config/assets/icons/
- { title: Grafana, url: ..., icon: "di:grafana" }            # logo from dashboard-icons (see below)
- { title: External, url: ..., icon: "https://cdn.example.com/x.png" }
- { title: Time,    url: ..., icon: "TI" }                    # up to two letters; without a value the initials of the title are used

About 120 icons are bundled (Lucide, ISC licence, see third_party/lucide/ in the repository). They are listed for browsing in docs/ui/icons.html; the configuration check reports unknown names. Put your own logos (SVG/PNG) into config/assets/icons/. Brand logos of third-party products are deliberately not bundled.

Logos from dashboard-icons

dashboard-icons offers about 3500 application logos (the same source as gethomepage). Use icon: di:<name>, for example di:grafana. Wegaria serves the files itself, so browsers never contact a third party (important for networks without internet and for the CSP). For this, a directory with the icons must be available:

icons: { dir: ../third_party/dashboard-icons }   # relative to wegaria.yaml; contains svg/, webp/, png/
  • In the repository the icons are a git submodule: git submodule update --init --depth 1 third_party/dashboard-icons. The SVGs alone are enough (63 MB instead of all formats): git -C third_party/dashboard-icons sparse-checkout set svg.
  • In the container none of this is in the image (brand logos). Mount the directory, for example ./dashboard-icons:/icons:ro, and set icons: { dir: /icons }.
  • Names are the file names without extension (di:home-assistant, variants such as di:github-light). SVG is preferred, then WebP, then PNG. Typos and a missing directory are reported to adminGroups as hints.
  • Docker labels: with icons.dir, homepage.icon: grafana or grafana.png means the logo di:grafana. wegaria.icon is taken literally (di:grafana, lucide:..., file name). See Applications.
  • A di: icon without icons.dir is rejected by the configuration check.
  • The brands belong to their owners; the repository only refers to dashboard-icons and does not ship the logos.
