Service area

service: { dir: content } enables categories, FAQ pages, search and forms. Content consists of files, which keeps it git-friendly.

service:
  title: Service       # name of the area in the navigation (default "Service")
  dir: content         # content directory relative to the config file (default "content")

Content layout

content/
  workplace/
    category.yaml            # title, description, order, icon, access
    overview.md              # optional introductory text
    _assets/banner.jpg       # banner.* is shown at the top; images in text: ![x](_assets/image.png)
    printers/
      category.yaml
      install-printer.faq.md           # front matter: title, summary, tags, access, related: [form-id], featured
      printer-problem.form.yaml        # form (see below)
  • IDs are paths (workplace/printers/printer-problem) and stay stable even if the content changes.
  • access is inherited downwards. Content that is not visible answers with 404 and appears neither in lists nor in the search.
  • Markdown does not allow raw HTML; javascript: links are discarded.
  • Broken files do not take the site down: the last good version stays active, and administrators see the errors at the top of the page.
  • In the YAML short notation { ... }, texts containing a comma must be quoted (title: "Accounts, devices"), otherwise YAML cuts them off. Wegaria recognises the rest as a key without a value and reports it to the administrators as a hint (the file stays active).

FAQ pages

FAQ pages are Markdown files named *.faq.md. Front matter fields:

Field Meaning
title, summary, tags Title, short text and tags (also searched).
access Who may see the page, in addition to the rules of its category.
related Ids of related forms, for example workplace/printers/printer-problem. Shown as "Problem nicht gelöst?" (problem not solved?).
apps Ids of the applications (tiles) this page documents; it is listed on their application page.
group Heading under which the page is listed on an application page (default: the title of its category).
featured true lists the page on the service start page.
order Sort order (default 100).

Side columns and the service start page

  • A FAQ page shows on the right the application(s) from its apps: (only those the user may see), the request from related: ("Problem nicht gelöst?") and further entries of the category.
  • A form shows the application(s) from apps:, pages that refer to it ("Vorher nachlesen", read this first) and what happens with the data (retentionDays, history).
  • The service start page puts questions and requests side by side. Which pages appear there is decided with featured: true (in the front matter of a FAQ page or in the header of a form). At most eight are listed, sorted by order and title, each with its area. If nothing is marked featured, the start page shows a simple selection of the first pages.

Forms

A form is a *.form.yaml file:

title: Report a printer problem
access: { groups: [staff] }          # public: true allows anonymous submissions
retentionDays: 90                    # keep answers this long
featured: true                       # list on the service start page (optional)
history: true                        # users can see their own submissions
rateLimitPerMinute: 5
prefill: { contact: user.name }      # question -> user.id | user.name | user.email
apps: [printing]                     # tile ids this form belongs to (optional)
actions:
  - type: email
    to: [it-support@example.com]
    subject: "Printer problem from {{user.name}}"
    body: "{{answers}}"              # also {{answer.<question>}}, {{submission.id}}, {{form.title}}
                                     # dynamic panels: {{#each <panel>}}{{@number}}. {{field}}\n{{/each}} (at most 100 entries)
    replyToUser: true
  - { type: webhook, target: helpdesk }   # targets are defined in wegaria.yaml (never put secrets in content)
  - { type: git, target: archive }
survey:                               # SurveyJS JSON (paste a Creator export)
  elements:
    - { type: text, name: contact, title: Your name, isRequired: true }
Field Default Meaning
title required Form title.
access inherited public: true allows anonymous submissions.
retentionDays 90 How long answers are stored in days. 0 keeps them only until all actions are delivered. Data protection: see below.
history false Users see their own submissions on /my (requires retentionDays greater than 0).
featured false List on the service start page.
rateLimitPerMinute 5 Submissions per minute (one bucket per form).
prefill {} Pre-fill a question with an attribute of the signed-in user: user.id, user.name or user.email.
apps [] Tile ids this form belongs to; it is listed on their application page.
actions – What to do with a submission (below).
survey required The SurveyJS model as JSON.

Validation

The server checks every submission with the same engine as the browser (required fields, validators, visibleIf). Unknown fields and answers to hidden questions are discarded.

The rate limit for anonymous forms is coarse (one bucket per form). Add a honeypot or captcha if you need more protection.

Not supported: choicesByUrl and file and signature questions. They are rejected when the file is loaded.

Actions

Actions run in the background through a queue in SQLite: up to 6 attempts (after 1 min, 5 min, 30 min, 2 h, 12 h), then the state is failed. Everything is in the audit log (form.submitted, action.ok, action.error, action.failed). Failed actions can be retried in the administration.

  • email: a plain-text mail through smtp. The subject is made single-line (no header injection). Fields: to (list), subject, body, replyToUser (set Reply-To to the submitter's address; default false).
  • webhook: a JSON POST with the headers x-wegaria-timestamp and x-wegaria-signature: sha256=HMAC(secret, "<timestamp>.<body>"), a timeout, no redirects; success means a 2xx response.
  • git: writes <form>__<reference>.json into the repository and commits (one operation per repository at a time, optional push).

Targets and credentials live in wegaria.yaml, never in the content:

smtp:
  host: smtp.example.com
  port: 587              # default 587
  secure: false          # true = implicit TLS (port 465); otherwise STARTTLS is used automatically
  user: wegaria
  password: ${file:/run/secrets/smtp}
  servername: smtp.example.com   # optional: TLS server name (SNI) if it differs from host
  from: "Wegaria <wegaria@example.com>"
targets:
  helpdesk:
    type: webhook
    url: https://helpdesk.example.com/hooks/wegaria
    secret: ${file:/run/secrets/helpdesk_hook}   # HMAC key, at least 16 characters
    headers: { x-token: abc }                     # optional
    timeoutMs: 10000                              # default 10000, max. 60000
  archive:
    type: git
    dir: /archive          # absolute working directory of the repository
    init: false            # git init if the directory is not a repository yet
    push: false
    authorName: Wegaria
    authorEmail: wegaria@example.com

The git action needs git in the runtime (the container image includes it). For the container setup see Deployment.

Data protection

Answers often contain personal data. They are deleted after retentionDays (only once nothing remains to be delivered); records and audit entries are deleted after auditRetentionDays (top-level setting, default 365).

CSRF

Submissions are JSON POSTs and are accepted only with a matching Origin. Set baseUrl, or pass Host/X-Forwarded-Host through correctly.

Data is stored in $WEGARIA_DATA/wegaria.sqlite3 (default ./data).

Appearance of forms

SurveyJS 3 is loaded with its official themes (light/dark, flat). The grey scale and the brand colour are mapped to the Wegaria colours, so fields, switches, ratings and buttons are readable in both modes. For a custom look, export a theme from the SurveyJS theme editor and put it into config/assets/<name>.json (branding.surveyTheme: <name>.json). Its cssVariables apply in addition to the Wegaria defaults.

demo/content/it-support/feldtypen.form.yaml in the repository shows all common question types for testing.

My requests ("Meine Anfragen")

/my shows signed-in users their own submissions for forms with history: true. Answers are shown only as long as they are stored according to retentionDays.

Administration

/admin is available to members of adminGroups only; for everyone else it answers 404. It contains:

  • key figures,
  • failed actions, with "Erneut versuchen" (retry),
  • submissions (filterable with ?form=<id>),
  • details with answers, and the audit log,
  • the notice editor at /admin/notices when incidents.editable is on.

Opening a submission is logged as admin.view.

CSV export

/admin/export.csv?form=<id> returns all submissions of a form with one column per question (only answers that are still retained). Without form, only the overview without answers is exported.

  • Encoding is UTF-8 with BOM. The delimiter is ; when lang: de and , otherwise.
  • Cells that Excel would execute as a formula (starting with =, +, - or @) are defused with a leading '.
  • Every export is in the audit log as admin.export.

Audit events

form.submitted, action.ok, action.error, action.failed, action.retry, data.purged, admin.view, admin.export, notice.created, notice.updated, notice.deleted, and with native OIDC auth.login, auth.logout, auth.groups_changed, auth.revoked, auth.backchannel_logout.
